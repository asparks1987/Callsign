Test Plan

Purpose

v1.0 alpha is proven when the Free open-source core works end-to-end from install through visible launch.

All Alpha v1 features are free and remain free until at least beta.

v1.0 automated coverage

Default smoke command:

dotnet run --project tests/Callsign.AlphaSmoke/Callsign.AlphaSmoke.csproj

Required checks:

  • fresh install/service startup assumptions
  • profile creation and local settings persistence
  • wake-only speech does not launch
  • wake word detection and identity gate for Callsign / call sign
  • enrollment sample proof includes fresh distinct hashes plus quality metadata for peak/RMS, duration, clipping ratio, and noise-oriented zero-crossing rate
  • callsign.gif appears and session readout updates while active, including visible wake-overlay safety text for stop/cancel and identity-before-command behavior
  • identity success and mismatch handling
  • session-state invariant tests proving fresh identity authorization is valid only during active command/launch states and is cleared on completed, timed-out, cancelled, or locked-out terminal states
  • visible Start menu launch path
  • safe stop, cancel, timeout, and lockout handling
  • runtime snapshot includes session state, transcript, overlay readout, and microphone telemetry
  • runtime control diagnostics redact scripted transcript text and log only length/hash metadata
  • runtime temporary audio cleanup deletes stale segment, wake-window, and wake-warmup WAV files while retaining only fresh diagnostics
  • unsafe launch text, paths, URLs, shell fragments, secret-like inputs, and administrative/elevated tooling are rejected

Release gate

No v1.0 alpha release until:

  • build site and installer are reproducible,
  • service/session fields are readable in runtime state,
  • overlay is visible at wake and hidden in terminal states,
  • identity failures remain safe and visible,
  • common app launches work through visible flow,
  • and docs/website accurately describe open-source Free plus future closed-source extensions.

Parity gate

1.0.0a is the first release that claims practical Windows 11 Voice Access parity. No release can claim parity until every row in VOICE_ACCESS_PARITY_MATRIX.md is Done and automation + manual evidence is attached to each row. Run .\scripts\voice_access_parity_evidence.ps1 before any parity claim, or use .\scripts\prepare-release-packet.ps1 to run the release-readiness build/site steps plus the parity smoke/template flow together. The generated JSON separates local evidence success from release proof: passed means the automated/documentation checks completed, while release_ready is true only when manual/live parity evidence is supplied and no evidence checks fail. It reports canonical_manual_evidence.categories_missing to prove the generated manual walkthrough template covers every parity category, and manual_evidence.categories_covered / manual_evidence.categories_missing to show which categories have actual submitted live evidence. Use -RequireManualEvidence on the parity or packet scripts when validating a release candidate so missing live walkthrough evidence fails the gate instead of being treated as implied completion. Manual evidence must contain passed named checks for clean install from the public installer, installed end-to-end automated checks, human-spoken core walkthrough, failure-state walkthrough, clean Windows user or VM test, enrollment, identity failure/cancel/reset, show numbers/grid, dictation, browser, window/settings, keyboard/mouse/media/file workflows, command discovery, browser overlay helper discovery from the walkthrough, local voice shortcuts create/manage/execute, community extension import/manage, release evidence folder access, update splash and imported-pack splash replay, visible Updates-status readback, visible visual-status readback, Apple Voice Control-style visual polish across the core visible surfaces, compact STOP badges and stop/cancel boundary copy on the wake overlay, visible-controls HUD, mouse grid, command palette, startup walkthrough, update splash, and import splash, and public website installer hash comparison. A passed apple_style_visual_polish_walkthrough must also complete the generated accessibility visual audit for keyboard-only operation, logical tab order, visible focus, screen-reader labels, no color-only state, high contrast, 200% text scaling, reduced motion, multi-monitor/DPI behavior, no-audio fallback, visible stop/cancel affordances, and non-focus-stealing overlays. .\scripts\voice_access_parity_evidence.ps1 -WriteManualEvidenceTemplate now also writes build/voice-access-parity-manual-evidence.checklist.md and build/manual-proof-notes/*.md so the live walkthrough can be followed as a human-readable checklist with one per-check note beside the canonical JSON template. To prepare that file, run .\scripts\voice_access_parity_evidence.ps1 -WriteManualEvidenceTemplate. The generated canonical template is written to build/voice-access-parity-manual-evidence.template.json and includes every required check id, a description, a concrete evidence_command walkthrough prompt, an expected_result proof target, parity_categories, the local installer hash and byte size, and placeholders for public website download hash, public website byte size, machine details, operator, timestamps, observed result, artifact references, privacy review, and notes. Strict validation requires the supported manual-evidence schema, unique manual check ids, valid evidence timestamps, a public Callsign-Setup.exe download URL, test machine, Windows version, Callsign version, a timestamp, operator, environment, and notes for every manual check. It also requires the manual local and website installer SHA-256 values and byte sizes to match the current local Callsign-Setup.exe. Each manual check's description, evidence_command, expected_result, and parity_categories must also match the generated canonical template, so stale copied evidence cannot silently satisfy a newer parity walkthrough. Any check marked passed must include an observed_result, at least one artifacts reference such as a screenshot, video, transcript, audit log, hash output, or manual test note file, and a completed privacy_review checklist confirming no raw audio, no personal transcript, redacted paths/usernames, no tokens/secrets, and reviewed screenshots. Artifact references must be HTTP(S) URLs with evidence-file extensions such as .png, .mp4, .json, .jsonl, .log, .md, .txt, .pdf, or .zip, or existing local files inside the Callsign workspace using either absolute paths under the repo or repo-relative paths. The generated canonical JSON and human-readable checklist both begin with the documentation-pack evidence header for commit, build ID, artifact hashes, tester, Windows build, machine or VM, microphone, install mode, UI/runtime versions, and wake/identity/transcription models before the per-check walkthrough prompts. Submitted manual evidence must fill that evidence_header, including a valid tested UTC timestamp with UTC offset zero and artifact hashes that name the current local Callsign-Setup.exe SHA-256, before the release gate can pass. Each checklist item also carries pass/fail/blocked, observed-result, evidence-path, sensitive-data review, remaining-uncertainty, and release-recommendation fields so the human notes mirror the strict JSON validation contract.

For a release candidate, prefer .\scripts\prepare-release-packet.ps1 so the build/site verification, parity evidence JSON, canonical manual-evidence template, alpha walkthrough evidence JSON, website installer verification, and build/release-packet-summary.json are produced together from one command. Pass the public website URL plus the known website installer hash and size so the template and summary carry the same release metadata the verifier uses. The alpha walkthrough checklist writes build/alpha-v1-walkthrough-evidence.json, and the packet summary now records that file path plus a walkthrough discovery summary, the parity evidence release_blocker_summary, and the documentation-pack release gates for installed end-to-end automation, human-spoken core walkthrough, failure-state walkthrough, and clean Windows user or VM proof so the scripted walkthrough proof stays linked to the release packet. .\scripts\alpha_v1_checklist.ps1 -Verify now also expects the generated build/voice-access-parity-manual-evidence.checklist.md companion, validates that the release packet carries the structured parity blocker summary with blocker count, next action, manual-check count, and automated-failure count, and copies that summary into build/alpha-v1-walkthrough-evidence.json so the manual proof pass stays human-readable and machine-checkable. .\scripts\verify-release-readiness.ps1 validates the manual evidence template schema, evidence header, at least 40 manual/live checks, checklist content, at least 40 checklist sections, and the build/manual-proof-notes folder with at least 40 markdown notes whenever the manual evidence template exists; each note must keep the required evidence command, expected result, observed result, artifact reference, privacy review, uncertainty, and release recommendation sections. If the Pi is unavailable, -LocalPreviewOnly keeps the same packet flow alive against the local website container, still verifies the local /downloads/Callsign-Setup.exe endpoint, records the preview installer hash and size plus a release_mode of local-preview in the packet summary, and avoids rebuilding the site twice by skipping the second site build in the preview deploy helper.
